# Ardoise V2 — multi-projets, glisser-déposer, vue Liste

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Surcharges du `CLAUDE.md` de l'utilisateur** (prioritaires sur le skill) : **un seul commit pour tout le plan** — ignorer les commits par tâche ; **aucune revue par tâche** — une seule revue finale ; les tâches sans dépendance partent **en parallèle** ; rapport de 10 lignes max par sous-agent.

**Goal:** Ardoise cesse d'être câblé sur un projet unique, les cartes se déplacent à la souris, et une vue Liste permet de retrouver une demande ancienne que le tableau (filtré par mois) ne sait pas montrer.

**Architecture:** On ne change pas la forme de l'app, on élargit son état. `Request` gagne un `projectId` ; le store porte une liste de projets et un projet courant, et tout ce qu'il expose déjà (colonnes, compteurs, sous-titre) se restreint au projet courant. La persistance passe d'une liste de demandes à un instantané `{projects, requests}`, avec reprise automatique des données V1. Le glisser-déposer et la vue Liste ne sont que des lectures/écritures de plus sur ce même store — aucune logique métier ne descend dans les widgets.

**Tech Stack:** Flutter 3.47 / Dart ^3.13.2 · `shared_preferences` ^2.5.6 · `google_fonts` ^9.0.0 · `flutter_test`. Aucune nouvelle dépendance : `Draggable`/`DragTarget` sont dans le framework.

**Spec:** `docs/handoff.md` §4 (hors périmètre V1) et §2 (modèle de données) ; `docs/prototype.html` pour le style ; décisions de cadrage du 08/10 (voir Global Constraints).

- **Décisions de cadrage du 08/10 :** vue Liste = tous mois confondus, avec recherche plein texte et tri ; **pas de sous-tâches, pas de pièces jointes** ; vue Votes reste inerte.
- `flutter analyze` sans avertissement et `flutter test` vert avant de rendre une tâche.
- Ne jamais appeler un `*TextTheme` de `google_fonts` (renvoie le `TextTheme` de `package:material_ui`, incompatible).
- Sous les contraintes lâches d'un `Wrap`, `Align`/`Center`/`Container(alignment:)` s'étirent : utiliser `Center(widthFactor: 1)` ou `Row(mainAxisSize: .min)`.

## Review Focus

Classes d'entrées que les décisions impliquent mais qu'aucun parcours heureux n'exerce.

1. **Reprise des données V1** — Damien utilise déjà l'app ; ses demandes enregistrées sous `chantier.requests.v1` doivent atterrir dans Échéo, pas disparaître. → Tâche 1.
2. **Projet vide** — colonnes vides, « 0 demande », progression 0 % sans division par zéro, et la numérotation repart à 1 (pas à 59). → Tâche 1.
3. **Clé de projet vide ou en doublon** — refusée à la création, sinon deux projets émettent `ECH-1` chacun et les références cessent d'identifier. → Tâche 1 (règle) + Tâche 3 (UI).

5. **Déposer une carte sur sa propre colonne** — aucun changement d'état, aucune écriture, aucune notification inutile. → Tâche 2.
6. **Recherche sans résultat** — un message explicite, pas une liste vide muette. → Tâche 3.

```dart
/// Ce que la persistance échange en un bloc : les projets et leurs demandes.
/// Les deux voyagent ensemble — une demande sans son projet n'a pas de sens.
class ArdoiseSnapshot {
  const ArdoiseSnapshot({required this.projects, required this.requests});

  final List<Project> projects;
  final List<Request> requests;

  Map<String, Object?> toJson() => {
    'projects': projects.map((p) => p.toJson()).toList(),
    'requests': requests.map((r) => r.toJson()).toList(),
  };

  factory ArdoiseSnapshot.fromJson(Map<String, Object?> json) =>
      ArdoiseSnapshot(
        projects: (json['projects']! as List)
            .cast<Map<String, Object?>>()
            .map(Project.fromJson)
            .toList(),
        requests: (json['requests']! as List)
            .cast<Map<String, Object?>>()
            .map(Request.fromJson)
            .toList(),
      );
}
```

`Project` gagne son propre couple JSON (la couleur passe en `int`) :

```dart
  Map<String, Object?> toJson() => {

    'milestoneName': milestoneName,

    'color': color.toARGB32(),
  };

  factory Project.fromJson(Map<String, Object?> json) => Project(

    key: json['key']! as String,
    name: json['name']! as String,
    milestoneName: json['milestoneName'] as String? ?? '',
```

```dart
abstract class ArdoiseRepository {
  /// `null` quand il n'y a rien d'exploitable : premier lancement, ou
  /// données illisibles. L'appelant repart alors des données d'exemple.
  Future<ArdoiseSnapshot?> load();

  Future<void> save(ArdoiseSnapshot snapshot);
}

class PrefsRepository implements ArdoiseRepository {
  static const storageKey = 'chantier.snapshot.v2';

  /// Clé de la V1 : une liste nue de demandes, toutes d'Échéo.
  static const legacyKey = 'chantier.requests.v1';

  @override
  Future<ArdoiseSnapshot?> load() async {
    // `getInstance()` doit rester DANS le `try` : il échoue quand le
    // navigateur bloque les données de site, et le contrat de `load` est de
    // ne jamais lever — sinon l'app reste figée sur son chargement.
    try {
      final prefs = await SharedPreferences.getInstance();
      final raw = prefs.getString(storageKey);
      if (raw != null) {
        final decoded = jsonDecode(raw);
        if (decoded is! Map<String, Object?>) return null;
        return ArdoiseSnapshot.fromJson(decoded);
      }
      return _loadLegacy(prefs);
    } on Object {
      return null;
    }
  }

  /// Reprise V1 → V2. On ne supprime pas l'ancienne clé : elle ne coûte
  /// rien et sert de filet si on revient en arrière.
  ArdoiseSnapshot? _loadLegacy(SharedPreferences prefs) {
    final raw = prefs.getString(legacyKey);
    if (raw == null) return null;
    final decoded = jsonDecode(raw);
    if (decoded is! List) return null;
    final requests = decoded
        .cast<Map<String, Object?>>()
        .map(Request.fromJson) // `projectId` absent → 'echeo'
        .toList();
    // Le projet d'accueil doit exister, sinon les demandes sont orphelines.
    return ArdoiseSnapshot(
      projects: [seedProjects.firstWhere((p) => p.id == 'echeo')],
      requests: requests,
    );
  }

  @override
  Future<void> save(ArdoiseSnapshot snapshot) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(storageKey, jsonEncode(snapshot.toJson()));
  }
}
```

`MemoryRepository` suit, signature exacte (les trois fichiers de test en dépendent) :

```dart
class MemoryRepository implements ArdoiseRepository {
  MemoryRepository([ArdoiseSnapshot? initial]) : stored = initial;

  ArdoiseSnapshot? stored;

  /// Si non nul, `save` lève — pour tester le bandeau d'erreur.
  Object? failWith;

  /// Si non nul, `load` lève — pour tester qu'un dépôt en panne ne laisse
  /// pas l'app figée sur son indicateur de chargement.
  Object? loadFailsWith;

  @override
  Future<ArdoiseSnapshot?> load() async {
    if (loadFailsWith != null) throw loadFailsWith!;
    return stored;
  }

  @override
  Future<void> save(ArdoiseSnapshot snapshot) async {
    if (failWith != null) throw failWith!;
    stored = snapshot;
  }
}
```
